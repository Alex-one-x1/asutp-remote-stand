# Занятие 20 — Modbus TCP

Шлюз Modbus TCP → RTU `tcp_gateway.py` на pi3: TCP 5020 → конвертер CH340, 9600 8N1. Клиент — QModMaster на Windows, 192.168.1.111:5020.

## RTU и TCP

    RTU:  [адрес устройства] [PDU: функция · данные] [CRC]
    TCP:  [MBAP 7 байт]      [PDU: функция · данные]

MBAP: transaction id (2) · protocol id = 0 (2) · length = unit id + PDU (2) · unit id (1).
В TCP нет CRC и паузы 3,5 символа; клиентов может быть много — шлюз пускает их на шину по очереди (замок), с паузой 20 мс между запросами.

## Один запрос с двух сторон

| Сторона | Запрос | Ответ |
|---|---|---|
| TCP (tcpdump) | `0004 0000 0006 01` + `04 0001 0002` | `0004 0000 0007 01` + `04 04 0118 01D3` |
| RTU (сниффер) | `01` + `04 0001 0002` + `20 0B` | `01` + `04 04 0118 01D3` + `3A 72` |

PDU одинаковый; шлюз меняет MBAP ↔ адрес устройства и CRC. 0x0118 = 28,0 °C, 0x01D3 = 46,7 %.

## Через шлюз

| Запрос | Ответ (TCP) | Смысл |
|---|---|---|
| unit 1, 04, рег. 0x0001, 2 | `00 01 00 00 00 07 01 04 04 01 0B 01 C8` | 26,7 °C, 45,6 %; полный путь 28 мс |
| unit 2, 01, рег. 0x0000, 8 | `00 02 00 00 00 04 02 01 01 00` | PDU 3 байта: функция, 1 байт, данные 00 |
| unit 5, 04, рег. 0x0001, 2 | `00 03 00 00 00 03 05 84 0B` через 202 мс | исключение 0B: шлюз жив, прибор не ответил |

## Решения

- При тишине прибора шлюз возвращает исключение 0B — клиент отличает молчание прибора от неработающего шлюза.
- Таймаут шлюза к прибору (0,2 с) меньше таймаута клиента к шлюзу (≈ 0,5 с).
- Порт 5020: 502 в Linux привилегированный. На объекте — 502.

## Наблюдения

- Опечатка в IP (162 вместо 192): QModMaster показал «Connecting … OK», шлюз подключения не увидел — проверка соединения по журналу сервера.
- Часы Windows и pi3 расходятся ≈ 16 с — журналы разных узлов без синхронизации времени не сопоставить.
- Через шлюз нельзя записать адрес релейного модуля: эхо функции 16 нестандартной длины шлюз принимает за битый ответ.
